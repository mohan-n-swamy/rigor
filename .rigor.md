## 1. Objective, then flawless

OBJECTIVE: a reader with Claude Code and no knowledge of Mohan's rig installs the package and, on their next session, is governed by rigor exactly as this rig is: asked before big work, blocked at the third file without a `.rigor.md`, blocked at "done" without evidence, and steered by ponytail against runaway scope.

FLAWLESS (with respect to fulfilling that objective): facts a stranger could check.

- Fresh `HOME`, `rigor install`, then `~/.claude/settings.json` holds exactly three rigor entries: PreToolUse matcher `Write|Edit|MultiEdit|NotebookEdit` → `rigor-gate.sh`; UserPromptSubmit → `rigor-gate.sh --ask`; Stop → `evidence-gate.sh` — `tests/test.sh` asserts the count and the commands.
- Running `rigor install` twice leaves the same three entries, not six — `tests/test.sh` asserts idempotence.
- `rigor uninstall` removes exactly those entries and files and nothing else in the user's settings — `tests/test.sh` diffs settings before install and after uninstall.
- The shipped gate can fail and can pass — `rigor self-test` exits 0 and prints the PASS red / PASS green lines from `rigor-gate.sh --self-test`.
- The pre-work gate blocks the third distinct file with no `.rigor.md` above it and allows it once a valid one exists — `tests/test.sh` feeds three PreToolUse JSON events and asserts exit 2, then writes a valid `.rigor.md` and asserts exit 0.
- The done-gate denies an untagged material claim and passes a tagged one — `tests/test.sh` feeds two Stop events.
- `rigor validate <file>` exits 0 on the sample in the self-test and 1 on the bare template — `tests/test.sh`.
- Ponytail is present: `canon/PONYTAIL.md` carries the MIT attribution line, and `rigor install` appends one marked block to `~/.claude/CLAUDE.md` importing it, or reports that `claude plugin install ponytail@ponytail` is the fuller path when the `claude` CLI is present — `tests/test.sh` asserts the marker block exists once after two installs.
- No secret, phone number, or private path from this rig ships — `grep -rEn '/Users/mohannarayanswamy|Orange Health|Kamakshi|91886' <package>` returns nothing.
- Homebrew formula installs and its test passes — `brew install --build-from-source Formula/rigor.rb && brew test rigor` exit 0.
- Zip unpacks to the same tree the repo holds — `unzip -l dist/rigor-v0.1.0.zip | grep -c bin/rigor` returns 1.
- The public repo exists only after Mohan says yes — HUMAN gate, recorded in the run log.

## 2. Must / must not

MUST:
- Ship the canon verbatim, with the Turiya attribution and URL intact.
- Keep the hook scripts byte-identical to the rig's except for the path constants named in section 3, so behaviour here and there is the same script.
- Install to the same paths the scripts already expect (`~/.agents/RIGOR-ALGORITHM.md`, `~/.claude/templates/rigor.md`) so no script needs a second code path.
- Merge into `settings.json` with `python3` JSON, never `sed`, and preserve every key the user already has.
- Register the new repo in `projects.yaml` with a wiki page, or `bin/generate-project-indexes.rb --check` goes red again.
- Ask Mohan before `gh repo create --public` and before pushing the tap formula (outward-facing writes).

## 3. Known failure modes and their prevention

| Failure | Seen where | Prevention |
|---|---|---|
| `git -C` fell through on a non-git dir and reported the vault's HEAD | this session (refresh queue, wa-pipe page) | every `git -C` here targets the new repo dir that `git init` created first; test asserts `.git` exists before any git call |
| Proxy-rewritten `find`/`grep`/`ls` | this session | `/usr/bin/find`, `/usr/bin/grep` in tests and gates |
| Classifier blocks bundled destructive commands | this session | installer and tests do one destructive action per statement; no `rm -rf` outside `mktemp -d` |
| Worker rewrote a file after "done" | this session (oh-clients, wa-pipe) | no deck workers on this job; everything native (the files are this rig's own) |
| A gate that never fails is not a gate | canon; rigor-gate self-test exists for this | `tests/test.sh` asserts both a block (exit 2) and an allow (exit 0) for each gate |
| Pre-commit slop lint chokes on vendored JS | this session (Obsidian plugins) | no JS shipped; all bash/python/markdown |
| Path constants scattered across scripts | rigor-gate has `CANON`, `TEMPLATE`, `STATE_DIR` at top | keep them there; evidence-gate gets one `RIGOR_CANON` variable for its deny text |
